# UH-60 clear-zone search regression

Date: 2026-07-25

Branch: `feature/jalalabad-airwing-phase1-functional-tests`

## Result

**FAIL before operation creation. No UH-60 was spawned.**

The same failure occurred in two consecutive attempts:

```text
RESULT testId=UH60_TROOP classification=FAIL
reason=operation-create-failed: no MOOSE clear position found in ZONE_AIR_US_JBAD_LOGISTICS_LOAD clearance=12m
authority=nil nativeState=CREATED released=false
births=0 takeoffs=0 objective=false rtb=false landings=0 duration=0.0s
```

The failure was generated by the project factory before `OPSTRANSPORT` was created. It was not caused by a Mission Editor trigger, an AIRWING asset, the UH-60 flight model or the transport lifecycle.

## Mission Editor geometry

The uploaded mission contains:

```text
ZONE_AIR_US_JBAD_LOGISTICS_LOAD
centre x=72579.193321936 y=389777.09608944
radius=27.432m

ZONE_TEST_US_JBAD_UH60_DROPOFF
centre x=73337.730420368 y=388358.23973509
radius=152.4m
```

The six units of `TPL_GROUND_BLUE_JBAD_PHASE1_UH60_TROOPS` are already positioned within the pickup zone at these distances from its centre:

```text
25.154m
26.097m
23.725m
24.235m
24.834m
23.284m
```

Therefore the Mission Editor fixture already contains the intended separation:

- pickup-zone centre: helicopter landing point;
- troop template near the zone edge: embarkation position;
- dropoff-zone centre: helicopter destination landing point.

The project code incorrectly ignored this authored geometry and required `ZONE_RADIUS:GetClearZonePositions(12, 100)` to produce an additional landing candidate inside a 27.432m zone. The function legitimately returned no candidate, and the project then aborted the operation.

## MOOSE-first review

The review followed `docs/26-moose-first-development-policy.md`:

1. Official MOOSE Develop documentation checked for `Ops.OpsTransport` and `Core.Zone`.
2. Pinned source commit checked:
   - `73d3ed119cd9e7e3f2cfcabbaa34513d30529b54`
   - `OpsTransport.lua`
   - `OpsGroup.lua`
   - `Zone.lua`
   - `Utils.lua`
3. Official MOOSE mission repositories checked for `OPSTRANSPORT` examples. The official class documentation provides the constructor-based transport example; no setter-specific official mission example was available through the indexed repository search.

Confirmed public MOOSE responsibilities:

```text
OPSTRANSPORT:SetPickupZone()       carrier pickup landing zone
OPSTRANSPORT:SetEmbarkZone()       cargo embarkation zone
OPSTRANSPORT:SetDeployZone()       carrier destination landing zone
OPSTRANSPORT:SetDisembarkZone()    cargo disembarkation zone
ZONE_RADIUS:New()                  runtime radius zone
SPAWN:Spawn()                      spawn at authored template position
```

`ZONE_RADIUS:GetClearZonePositions()` is a valid MOOSE method, but it is intended to search for clear ground positions and can return `nil`. It is not required when the mission author has already supplied a verified landing point.

## Correction

Removed from `13-phase1-mission-factory.lua`:

- `GetClearZonePositions()` calls;
- clear-position candidate selection;
- custom distance and separation selection;
- the operation-create failure dependency on a returned clear candidate.

The corrected factory now uses:

```text
Pickup carrier landing:
  5m runtime ZONE_RADIUS at the centre of ZONE_AIR_US_JBAD_LOGISTICS_LOAD

Troop embarkation:
  original Mission Editor position of TPL_GROUND_BLUE_JBAD_PHASE1_UH60_TROOPS

Deploy carrier landing:
  5m runtime ZONE_RADIUS at the centre of ZONE_TEST_US_JBAD_UH60_DROPOFF

Troop disembarkation:
  original ZONE_TEST_US_JBAD_UH60_DROPOFF objective zone
```

Applied public MOOSE APIs:

```lua
transport:SetPickupZone(pickupLandingZone)
transport:SetEmbarkZone(pickup)
transport:SetDeployZone(deployLandingZone)
transport:SetDisembarkZone(objectiveDeploy)
```

No Mission Editor trigger, trigger condition, zone name, zone radius, zone position or template position was changed.
